# ERD와 테이블 관계 (1:N, N:M)

## ERD의 3가지 핵심 구성 요소

| 구성 요소 | 표현 방법 | 의미 |
|---|---|---|
| Entity(엔티티) | 사각형 | 데이터베이스의 하나의 테이블 |
| Attribute(속성) | 열(컬럼) | 테이블이 가진 각 항목 |
| Relationship(관계) | 선과 기호 | 테이블 간의 연결 (까마귀발 표기법 등) |

## 관계형 데이터베이스의 기본 구조: 테이블

관계형 데이터베이스(RDBMS)는 데이터를 **테이블**이라는 2차원 구조에 저장하며, 행(Row)과 열(Column)로 구성된다. 이는 엑셀 같은 스프레드시트와 유사한 형태다.

## 까마귀발 표기법 (Crow's Foot Notation)

```
회원 ||──O< 주문
```

- `||` : 정확히 1개(필수)
- `O<` : 0개 이상

즉 회원 한 명은 0개 이상의 주문을 가질 수 있고, 주문 하나는 반드시 한 명의 회원과 연결된다 → **1:N 관계**.

## N:M 관계는 직접 표현할 수 없다 → 중간 테이블(Junction Table)

학생과 강의처럼, 한 학생이 여러 강의를 들을 수 있고 하나의 강의에도 여러 학생이 있는 **N:M 관계**는 데이터베이스에서 직접 표현할 수 없다. 반드시 **중간 테이블**을 만들어 두 개의 1:N 관계로 분리해야 한다.

```
학생 (1) ── (N) 수강 (N) ── (1) 강의
```

- 학생 : 수강 = 1 : N
- 강의 : 수강 = 1 : N

❌ 잘못된 방법: 강의 테이블에 학생 목록을 콤마로 구분해 저장하는 것 — 정규화되지 않은 방식으로 실무에서 쓰지 않는다.

### 도서 대여 예시

한 사람은 여러 권의 책을 빌릴 수 있고, 하나의 책도 (시간을 두고) 여러 사람에게 빌려질 수 있으므로 **N:M 구조**가 맞다. `members`, `books`, `loans` 세 테이블을 조인해서 다룬다.

## ERD에 최소한 보여야 하는 것

```
members
books
loans
  - 각 테이블의 PK
  - loans.member_id (FK)
  - loans.book_id (FK)
  - 주요 속성
  - 1:N 관계 표시
```

## 실전 설계 포인트

- 한 행 = 하나의 엔티티(예: 학생 한 명)
- PK는 보통 자동 증가하는 `id`
- `email` 처럼 값이 중복되면 안 되는 컬럼은 `UNIQUE` 제약
- `학번` 처럼 중복되면 안 되거나 반드시 값이 있어야 하는 컬럼은 `UNIQUE` 또는 `NOT NULL`

## 아파트 비유로 이해하는 PostgreSQL 구조

| PostgreSQL 개념 | 비유 |
|---|---|
| PostgreSQL Server | 아파트 단지 |
| Database | 아파트 한 동 |
| Schema | 한 동 내부의 구역 |
| Table | 실제 물건을 보관하는 서랍 |
