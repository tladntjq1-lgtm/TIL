프로젝트 기간이라 일일 기록 대신 프로젝트 내용을 정리했다. 이번 글은 Django 프로젝트를 처음부터 세팅하고, PostgreSQL 데이터베이스를 연결하기까지의 과정이다.

한 줄 정리

  • 가상환경 생성 → 패키지 설치 → startproject / startapp 순서로 프로젝트 뼈대를 만든다.
  • 새 앱은 만들자마자 INSTALLED_APPS에 등록해야 Django가 인식한다.
  • DB 접속 정보는 settings.py에 직접 쓰지 않고 .env로 분리하며, search_path로 사용할 스키마를 지정한다.

1. 프로젝트 초기 세팅

프로젝트 폴더를 만들고, VS Code를 연 뒤, 가상환경을 만들어 활성화하고 필요한 패키지를 설치했다.

mkdir C:\dev\django_members
cd C:\dev\django_members
code .

python -m venv .venv                 # 오류가 나면 한 번 더 실행
.\.venv\Scripts\Activate.ps1          # 가상환경 활성화

pip install django "psycopg[binary]" python-dotenv
python -m pip install --upgrade pip
pip list
pip freeze > requirements.txt
  • django : 웹 프레임워크 본체
  • psycopg[binary] : Python에서 PostgreSQL에 접속하기 위한 드라이버
  • python-dotenv : .env 파일의 값을 불러오는 도구
  • pip freeze > requirements.txt : 설치된 패키지 목록을 파일로 저장한다.

.venv를 만든 뒤 Scripts 폴더 안에 pip.exe, python.exe, Activate/Deactivate 스크립트가 있는지 확인하면 정상 생성된 것이다.

2. 프로젝트와 앱 생성

django-admin startproject config      # settings.py와 urls.py가 들어있는 핵심 폴더
python manage.py startapp members     # members 앱 생성
python manage.py runserver
  • startproject config : settings.py와 urls.py가 들어 있는 핵심 설정 폴더(config)를 만든다.
  • startapp members : 기능 단위인 members 앱을 만든다.
  • runserver : 개발 서버를 실행한다.

새로 만든 앱은 settings.py의 INSTALLED_APPS 리스트 맨 끝에 앱 이름("members")을 추가해 줘야 Django가 인식한다.

INSTALLED_APPS = [
    # ... 기존 항목들 ...
    "members",   # 새 앱은 리스트 맨 끝에 추가
]

위 INSTALLED_APPS 코드는 이해를 돕기 위한 예시다. 기존 항목은 생략했다.

3. PostgreSQL 연동과 스키마 지정

settings.py의 DATABASES에 PostgreSQL 접속 정보를 적는다. 실제 값은 모두 ...로 가려 두었다.

DATABASES = {
    "default": {
        "ENGINE": "django.db.backends.postgresql",
        "NAME": "...",
        "USER": "...",
        "PASSWORD": "...",   # .env로 관리, 절대 커밋하지 않는다
        "HOST": "...",
        "PORT": "...",
        "OPTIONS": {
            "options": "-c search_path=practice",  # practice 스키마를 우선 검색
        },
    }
}

OPTIONS의 search_path를 지정하면, 여러 스키마 중 원하는 스키마(예: practice)를 우선적으로 검색하도록 만들 수 있다.

4. 환경변수(.env)로 비밀정보 관리

DB 비밀번호나 API 키 같은 민감한 정보는 settings.py에 직접 쓰지 않는다.

  1. 민감한 값은 .env 파일에 따로 적는다.
  2. settings.py에서 python-dotenv로 .env를 불러온다.
  3. .env는 .gitignore에 등록해서 절대 커밋되지 않도록 한다.
  4. 팀원들과는 값이 비어 있는 .env.example만 공유한다.

5. 실습에서 겪은 점

  • startapp으로 앱을 만든 뒤 settings.py에 앱을 등록하는 걸 깜빡하면, 모델과 뷰가 인식되지 않아서 헤맬 수 있다. 새 앱을 만들 때마다 INSTALLED_APPS 등록을 세트로 기억한다.
  • DB 연동 오류가 나면 가장 먼저 .env 값, OPTIONS의 search_path, 그리고 PostgreSQL 서버가 실제로 떠 있는지부터 확인한다.
