오늘 데일리 퀘스트는 5문항 모두 정답이었다. 어제 단어 일치(tokenize와 set)로 검색하면서 겪은 한계를 의미 기반 검색이 어떻게 푸는지 정리한다.

오늘의 한 줄 정리

  • 임베딩은 텍스트를 숫자 배열(벡터)로 바꿔 의미 기반 비교를 가능하게 한다.
  • 코사인 유사도는 벡터의 방향이 얼마나 같은지 본다. 길이 차이에 따른 왜곡이 없다.
  • ANN은 정확도를 조금 양보하고 속도를 얻는 근사 검색이다.
  • temperature=0 은 RAG에서 무작위성을 줄여 일관된 사실 답변을 얻기 위한 설정이다.

1. 임베딩(Embedding): 문장을 숫자 배열로

임베딩은 텍스트의 의미를 고차원 공간의 숫자 배열(벡터) 로 바꾸는 기술이다. 컴퓨터가 문장의 의미를 이해하고 문장 간 유사성을 계산할 수 있게 해 준다.

"과제 제출 기한은 언제인가요?"  →  [0.012, -0.034, 0.101, ... ]   (숫자 1,536개)
용어 정체
임베딩 텍스트 → 벡터 변환 (의미 기반 연산을 가능하게 함)
토큰 분할 텍스트를 쪼개는 전처리
파인튜닝 모델 가중치를 재학습
캐싱 연산 결과를 재사용
  • OpenAI text-embedding-3-small은 문장 1개를 1,536차원 벡터(길이 1,536의 실수 배열)로 바꾼다.
  • 왜 필요한가: 어제 만든 검색은 문의와 문의는을 다른 단어로 봤다. 임베딩은 글자가 아니라 의미로 비교하므로 "문의 게시판"으로 물어도 문의는 ... 게시판에 남깁니다 섹션을 찾을 수 있다. 어제 실습에서 남은 숙제였다.
# 개념 이해용 예시 (OpenAI SDK)
from openai import OpenAI

client = OpenAI()
res = client.embeddings.create(model="text-embedding-3-small", input="과제 제출 기한은 언제인가요?")
vector = res.data[0].embedding
print(len(vector))   # 1536

2. 코사인 유사도: 방향이 얼마나 같은가

두 벡터를 비교하는 방법은 여러 가지인데, 자연어 검색에서는 코사인 유사도(Cosine Similarity) 가 가장 표준적이다.

cos θ = (A · B) / (‖A‖ × ‖B‖)
방식 보는 것 특징
코사인 유사도 두 벡터의 사잇각(방향 일치도) 벡터 크기와 무관해서 문서 길이 차이로 인한 왜곡이 없다
유클리디안 거리 두 점 사이의 직선 거리 크기 차이에 민감하다
  • 값이 1에 가까울수록 방향이 같다(의미가 비슷하다).
  • 비유: 두 사람이 같은 방향을 가리키는지를 본다. 얼마나 멀리 서 있는지(크기)는 보지 않는다. 긴 문서와 짧은 문서가 같은 내용을 말해도 벡터의 크기만 다를 뿐 방향은 비슷하다.
  • 해밍 거리, 맨해튼 거리는 교안에서 비교 대상으로 언급되지 않은 다른 방식이다.

3. ANN: 정확도를 조금 양보하고 속도를 얻는다

벡터 데이터베이스에 벡터가 아주 많아지면 질문 벡터를 모든 벡터와 하나씩 비교하기가 너무 느려진다.

방식 동작 장단점
완전 전수 탐색 (Brute-force, K-NN) 모든 벡터를 비교 정확하지만 데이터가 많아질수록 느려진다
ANN (Approximate Nearest Neighbor) 벡터 공간을 군집화해서 탐색 범위를 제한 일부 정확도(Recall)를 양보하는 대신 속도가 수천 배 빨라진다
  • 비유: 도서관에서 책을 찾을 때 전체 서가를 다 뒤지는 것(전수 탐색)과, 분류 코너부터 찾아가는 것(ANN)의 차이다. 가끔 엉뚱한 코너를 고르면 아쉬운 책을 놓칠 수 있다(정확도 양보).
  • 한 줄: ANN = "근사"이므로 약간 틀려도 되는 대신 빠르다. 전수 탐색과는 반대 개념이다.

4. temperature=0: 무작위성 최소화

RAG에서 LLM이 제공된 문맥에 기반한 일관된 사실 답변을 만들도록, 확률적 무작위성을 줄이는 파라미터가 temperature다.

# 개념 이해용 예시
model = ChatOpenAI(model="gpt-4o-mini", temperature=0)   # 교안: model 초기화 시 temperature=0
  • temperature가 높을수록 답이 다양해지고(창의적), 낮을수록 일관되고 보수적이다.
  • 사실 기반 응답이 중요한 RAG에서는 임의적 상상(환각)을 억제하려고 temperature=0으로 설정한다.
  • 답변 형식은 파라미터 이름과 값을 함께 temperature=0처럼 쓴다.
  • 참고(일반적인 설명): 0으로 둬도 모델 내부 구현에 따라 항상 100% 똑같은 답이 보장되지는 않는다. 환각을 줄이는 보조 수단이지 근거 없이 정확해지는 마법은 아니다. 근거는 어디까지나 검색으로 붙인 문맥이다.

5. 한 장으로 연결하기

[인덱싱]  문서 → 청크 → 임베딩(1,536차원 벡터) → 벡터 DB 저장
[질의]    질문 → 임베딩 → 코사인 유사도로 가까운 청크 검색 (대규모면 ANN)
          → 청크를 붙여 프롬프트 구성 → LLM(temperature=0) → 답변
질문 한 줄 답
텍스트를 벡터로 바꾸는 기술? 임베딩
text-embedding-3-small의 차원? 1,536
길이 왜곡 없는 표준 유사도? 코사인 유사도
속도를 위해 정확도를 조금 양보하는 색인? ANN
일관된 사실 답변을 위한 설정? temperature=0

6. 오늘의 결과

  • 5문항 전부 정답. 오답노트는 없다.
  • 지난 4번의 실수는 모두 부정 문제("해당하지 않는 것")였는데, 이번엔 부정 문제가 없었다. 다음에 부정 문제가 나오면 부정 표현에 먼저 표시하는 습관을 이어 가자.
  • 헷갈리기 쉬운 짝: 임베딩(변환) vs 리트리버(검색기), 코사인(방향) vs 유클리디안(직선 거리), ANN(근사·빠름) vs 전수 탐색(정확·느림).
