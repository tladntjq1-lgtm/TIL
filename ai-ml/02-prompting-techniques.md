# 프롬프팅 기법: Zero-shot, Few-shot, Fine-tuning, Context Engineering

고객 문의 메일을 특정 형식으로 분류시키고 싶을 때, 모델에게 원하는 패턴을 학습시키는 방법에는 비용과 방식이 다른 여러 옵션이 있다.

## Few-shot Prompting (퓨샷 프롬프팅)

지시문과 함께 **2개 이상의 입력-출력 예시 쌍**을 프롬프트에 직접 포함시켜, 모델이 원하는 출력 패턴을 즉시 인지하도록 만드는 기법. 모델의 가중치를 바꾸지 않고, **문맥 내 학습(In-Context Learning)** 을 통해 그 자리에서 패턴을 파악하게 만든다.

```
지시문: 아래 문의 메일을 [문의/불만/칭찬] 중 하나로 분류해줘.

예시1) 입력: "배송이 너무 늦어요" → 출력: 불만
예시2) 입력: "환불은 어떻게 하나요?" → 출력: 문의

입력: "상품 정말 만족스러워요!" → 출력: ?
```

## 비교: Zero-shot vs Few-shot vs Fine-tuning vs Context Engineering

| 기법 | 방식 | 비용 |
|---|---|---|
| **Zero-shot** | 예시 없이 지시문만으로 바로 요청 | 가장 저렴 |
| **Few-shot** | 지시문 + 예시 2개 이상을 프롬프트에 포함 | 저렴, 즉시 적용 |
| **Fine-tuning (파인튜닝)** | 모델 가중치 자체를 재학습으로 변경 | 고비용, 시간 소요 |
| **Context Engineering** | 프롬프트를 넘어서 모델에게 주어지는 전체 정보 환경(문서, 도구, 대화 기록 등)을 설계 | 상황에 따라 다름 |

- 예시가 전혀 없으면 **Zero-shot**, 예시를 프롬프트에 넣으면 **Few-shot** — 둘 다 모델 가중치는 그대로다.
- **파인튜닝**은 프롬프트 기법이 아니라 모델 자체를 바꾸는 것이라 훨씬 무겁고 비용이 크다.
- **컨텍스트 엔지니어링**은 단순히 프롬프트 문장을 잘 쓰는 것을 넘어, 모델이 참고할 전체 정보(검색 결과, 도구 목록, 이전 대화 등)를 어떻게 구성하느냐의 문제라서 "예시 2개를 넣는 것"과는 층위가 다르다.

## 헷갈렸던 포인트

"예시를 프롬프트에 넣어서 패턴을 즉시 학습시킨다"는 설명을 보고 반사적으로 "파인튜닝"을 골랐는데, 파인튜닝은 **모델 가중치를 바꾸는 것**이라 예시 프롬프트와는 전혀 다른 접근이다. "즉시" + "가중치 변경 없음" 키워드가 나오면 Few-shot을 먼저 떠올리기.
