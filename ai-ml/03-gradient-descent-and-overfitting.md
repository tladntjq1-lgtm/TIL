# 경사하강법의 학습률과 과적합

## 경사하강법(Gradient Descent) 가중치 업데이트 공식

```
w_new = w_old - α · (∂J/∂w)
```

- `w` : 가중치
- `α` (알파) : **학습률(learning rate)** — 한 번에 얼마나 이동할지 정하는 보폭
- `∂J/∂w` : 손실 함수 `J`를 가중치로 미분한 기울기(gradient)

## 학습률(α)이 너무 크면? — 오버슈팅(Overshooting)

학습률(보폭)을 지나치게 크게 설정하면, 최저점(최소 손실 지점)을 **지나쳐 버리는 오버슈팅**이 발생한다. 그 결과 오차가 줄어들지 않고 오히려 **발산**할 수 있다.

반대로 학습률이 너무 작으면:
- 학습 속도가 지나치게 느려진다.
- 로컬 미니멈(local minimum, 진짜 최저점이 아닌 곳)에 갇히기 쉽다.

> ⚠️ 헷갈렸던 포인트: 학습률이 너무 크면 "과적합(overfitting)"이 생긴다고 착각하기 쉬운데, **과적합은 학습률 문제가 아니라 데이터 분할(train/valid/test) 이 없거나 모델이 데이터를 암기할 만큼 충분히(또는 과도하게) 학습된 경우에 생기는 별개의 문제**다. 학습률이 너무 크면 생기는 문제는 오버슈팅/발산이다.

## 과적합(Overfitting)

모델이 훈련 데이터의 일반적인 패턴이 아니라 **정답을 통째로 외워버려서**, 한 번도 본 적 없는 새로운 데이터에서는 성능이 떨어지는 현상.

### 방지 방법: Train / Valid / Test 분리

```
전체 데이터 → Train(학습) / Valid(검증) / Test(최종 평가)로 분리
```

- **Train**: 모델이 실제로 학습에 사용하는 데이터
- **Valid(검증)**: 학습 중간에 성능을 점검하며 과적합 여부를 판단하는 데이터 (모델이 직접 학습하지는 않음)
- **Test**: 모든 학습이 끝난 뒤 최종 성능을 평가하는, 학습 과정에 전혀 사용되지 않은 데이터

이렇게 데이터를 나눠서 "학습에 쓴 데이터에서만 잘하는지"와 "본 적 없는 데이터에서도 잘하는지"를 구분해서 확인해야, 과적합 여부를 제대로 판단할 수 있다.
