# AI 활용 전략: 툴 스택과 데블스 애드버킷

## 툴 스택 (Tool Stack) — "역할 나눠서 협업하기"

**비유**: 요리할 때 한 사람이 재료 손질·요리·플레이팅을 혼자 다 하는 것보다, **재료 손질 담당, 요리 담당, 플레이팅 담당**을 따로 두고 순서대로 이어서 일하는 게 더 잘 된다.

단일 AI 서비스는 기억할 수 있는 양이나 잘하는 작업의 종류에 한계가 있다. 이 제약을 극복하기 위해, **특화된 여러 AI 도구(노트북LM, 퍼플렉시티 등)를 목적에 맞게 직렬(순서대로) 또는 병렬(동시에)로 조합**해서 하나의 복잡한 과제를 해결하는 전략을 **툴 스택**이라 부른다. 레고 블록을 이어 붙이듯 각 도구가 잘하는 부분만 가져다 쓰는 것이다.

```
예: 회의 녹음 요약(A 도구) → 요약 내용 팩트체크(B 도구) → 최종 발표자료 제작(C 도구)
```

## 데블스 애드버킷 (Devil's Advocate) — "일부러 트집 잡아달라고 부탁하기"

**비유**: 그림일기를 다 쓰고 나서, 엄격한 선생님에게 "이거 진짜 잘 쓴 거 맞아요? 흠 좀 잡아주세요!"라고 부탁하는 것.

기획서나 사업계획서의 초안을 쓴 뒤, AI에게 **"너는 이 프로젝트에 절대 투자하지 않을 깐깐한 투자 심사역이야, 문제점을 낱낱이 지적해줘"** 처럼 엄격한 비판자 역할(페르소나)을 부여해서, 논리적 허점이나 비현실적인 비용 측정 같은 문제를 **미리 발견**하는 기법이다.

### 헷갈리기 쉬운 비슷한 이름의 기법들

| 기법 | 실제 의미 |
|---|---|
| **데블스 애드버킷** | AI에게 엄격한 비판자 역할을 부여해 초안의 허점을 미리 찾아냄 |
| 스타일 트랜스퍼 | 특정 문체(스타일)를 다른 글에 이식하는 기법 |
| 바이브 코딩 | 대화하듯 AI와 주고받으며 개발을 진행하는 기법 |
| 러닝 코파일럿 | AI를 학습 동반자(튜터)로 활용하는 개념 ([etc/ai-tutor-workflow.md](../etc/ai-tutor-workflow.md) 참고) |

이 넷은 이름이 비슷하게 느껴질 수 있지만 층위가 다른 개념이므로, "**역할을 부여해서 비판을 받는다**"는 키워드가 나오면 데블스 애드버킷을 먼저 떠올리기.
