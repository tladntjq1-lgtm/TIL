# RAG 파이프라인: 인덱싱 단계와 질의 단계

## 1. RAG는 5단계, 두 구간으로 나뉜다

RAG(Retrieval-Augmented Generation)는 모델이 답하기 전에 **관련 문서를 찾아서 참고 자료로 붙여주는** 방식이다.

```text
[인덱싱 단계: 질문이 생기기 전에 미리 해두는 사전 작업 (배치)]
 ① 문서 수집(Loading) → ② 문서 분할(Chunking) → ③ 임베딩 및 저장(Embedding & Storing)

[질의 단계: 사용자가 질문을 입력한 즉시 실행되는 실시간 작업]
 ④ 검색(Retrieval) → ⑤ 생성(Generation)
```

| 구간 | 단계 | 언제 | 하는 일 |
|---|---|---|---|
| 인덱싱 | ① 수집 | 사전 | 문서를 불러온다 |
| 인덱싱 | ② 분할 | 사전 | 문서를 작은 조각(청크)으로 자른다 |
| 인덱싱 | ③ 임베딩·저장 | 사전 | 청크를 벡터로 바꿔 벡터 저장소에 보관한다 |
| 질의 | ④ **검색** | **질문 즉시** | 질문과 가장 비슷한 청크를 찾아온다 |
| 질의 | ⑤ 생성 | **질문 즉시** | 찾은 청크를 참고해 답변을 만든다 |

> 한 줄 기억법: **도서관 사서 비유.** ①~③은 책을 사 와서(수집) 챕터별로 나누고(분할) 색인 카드를 만들어 서가에 꽂아두는 일(임베딩·저장)이다. ④~⑤는 손님이 질문하면 서가에서 책을 찾아오고(검색) 그걸 보고 답해주는 일(생성)이다.

## 2. 텍스트 분할과 `chunk_overlap`

문서를 일정 크기로 자르면 문장이나 핵심 정보가 **중간에서 잘릴 수** 있다. 이를 막으려고 앞뒤 청크가 **일부 겹치도록** 설정하는 값이 `chunk_overlap`이다.

```python
# 개념 이해용 예시 (LangChain 방식)
from langchain_text_splitters import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=200,      # 청크 하나의 최대 길이
    chunk_overlap=20,    # 인접한 청크가 겹치는 길이 (문맥 유실 방지)
)
chunks = splitter.split_documents(documents)
```

- `chunk_size`: 한 조각의 크기 / `chunk_overlap`: 이웃 조각과 겹치는 길이.
- 교안 실습 코드에서는 `chunk_overlap=20`으로 설정해 문맥 유실을 방지했다.

## 3. 임베딩 vs 리트리버: 이름이 비슷해서 헷갈린다

| 용어 | 정체 | 단계 |
|---|---|---|
| **임베딩(Embedding)** | 텍스트를 **벡터(숫자 목록)** 로 바꾸는 일 | ③ 인덱싱 |
| **리트리버(Retriever)** | 벡터 저장소에서 질문과 가장 유사한 청크를 **찾아오는 검색기** | ④ 질의 |

```python
retriever = vector_store.as_retriever(search_kwargs={"k": 3})   # k = 가져올 청크 개수
docs = retriever.invoke("질문 내용")
```

- 교안 실습에서는 `vector_store.as_retriever()`로 리트리버를 만들고 `k`값으로 검색할 청크 개수를 지정했다. (위 코드는 개념 이해용 예시라 실제 교안 코드와 인자 모양이 다를 수 있다.)
- 문제에 "**가져오는/찾아오는** 검색기"라는 말이 나오면 리트리버, "**벡터로 변환**"이면 임베딩이다.

## 4. 병목 현상: 어느 단계가 문제인가

RAG 답변이 이상할 때는 **어느 단계에서 막혔는지** 나눠서 본다.

| 상황 | 문제 단계 |
|---|---|
| 올바른 문서가 검색되었는데도 모델이 **무시하고 지어낸다** | **생성 단계** (지시 불이행, 환각) |
| 필요한 문서 자체를 못 찾아온다 | 검색 단계 (또는 그 앞의 수집·분할·임베딩) |

> 3번 문제처럼 "검색기가 **올바른 문서를 찾아 전달했는데도**" 틀렸다면 검색은 이미 성공한 것이다. 남는 곳은 생성 단계다.

| 문항 | 내가 고른 것 | 정답 | 틀린 이유 |
|---|---|---|---|
| 1. 인덱싱 단계에 **해당하지 않는 것** | 임베딩 및 저장 | **검색(Retrieval)** | **부정 문제를 거꾸로 읽음.** 임베딩·저장은 인덱싱 단계가 맞다 |
| 5. 연관성 높은 청크를 가져오는 검색기 | 임베딩 | **리트리버(Retriever)** | 임베딩(변환)과 리트리버(검색기)를 혼동 |

- **1번**: 인덱싱 = 수집·분할·임베딩/저장 (질문 **전**), 검색은 질의 단계 (질문 **후**). 고른 "임베딩 및 저장"은 인덱싱에 **포함되는** 단계였다. 11-02, 11-03에 이어 **"해당하지 않는 것/옳지 않은 것" 문제를 놓친 것이 벌써 네 번째**다. 이제 습관으로 고정해야 한다: 문제를 읽자마자 **부정 표현에 동그라미**를 치고, 선지마다 "이건 맞는가?"를 판단한 뒤 **틀린 것 하나**만 고른다.
- **5번**: 임베딩은 "변환", 리트리버는 "찾아오기". 단계로 구분하면 임베딩은 ③(사전), 리트리버는 ④(질의).
- 맞힌 문제: 2번(`chunk_overlap`), 3번(생성 단계 병목), 4번(질의 단계 = 실시간 검색+생성).
