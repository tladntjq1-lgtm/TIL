## 배운 것

| 주제 | 배운 점 |
|---|---|
| **캐시 키** | 질문만이 아니라 **제품 코드, 설정, 동의어 파일 해시, 커밋**까지 넣어야 한다. 그래야 모델만 다른 질문(T830와 T835)이나 코드 변경 후에 **옛 답을 돌려주지 않는다** |
| **오거부의 원인** | "생성 판단"이 아니라 **생성 모델이 받은 상위 5개 발췌에 답이 없는 것**이었다. 즉 **검색 순위 문제**다 |
| **결과의 흔들림** | 같은 질문도 실행마다 **±1~2문항** 흔들린다. **한 번의 결과로 개선 여부를 판단하면 안 된다** |

## 막힌 점과 해결

| 문제 | 해결 |
|---|---|
| 손 채점이라 버전 비교가 어려움 | **지표를 자동 계산**하고, 예전 로그로 다시 계산해서 **손 채점과 같은지 검증** |
| Supabase 팀 계정에는 스키마 생성 권한이 없음 | 코드에 박힌 `rag` 스키마를 **설정으로 바꾸고**, 이미 있으면 만들지 않게 함 |
| DBeaver에서 "Unknown host" | Host 칸에 **"Session pooler"라는 글자**가 들어가 있었다 |

## 정리

- 평가는 **자동 계산 + 회귀 비교**로 해야 버전 간 비교가 가능하다.
- 캐시는 **키에 넣는 값이 곧 정확성**이다.
- 오거부처럼 보여도 원인은 **검색 단계**일 수 있다. 생성 단계만 보지 않는다.
