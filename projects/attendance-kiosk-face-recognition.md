# 출석 키오스크 + 얼굴 인식 시스템

Django 기반으로 만든 팀 프로젝트의 출석 관리 기능 관련 메모. (실제 서버 주소·계정 정보는 보안상 이 문서에는 기록하지 않는다.)

## 서비스 구조: 컨테이너는 2개뿐

가장 헷갈렸던 부분: **"키오스크"는 별도로 실행되는 독립 프로그램이 아니다.** Django 안에 있는 하나의 페이지(URL)일 뿐이며, 로그인 페이지·근태 화면·마이페이지와 동일한 성격이다.

```bash
docker compose up web face-service
```

| 컨테이너 | 역할 |
|---|---|
| `web` | Django 전체 (로그인, 근태, 팀 정보, 키오스크 페이지까지 전부 포함) |
| `face-service` | 얼굴을 비교해주는 전용 서버 |

`web`과 `face-service` 두 컨테이너만 켜면, 그 안에 포함된 "키오스크 페이지"는 자동으로 함께 열린다. 서버에서는 터미널을 계속 열어둘 수 없으므로 `-d`(detached) 옵션을 붙여 백그라운드로 띄운다.

```bash
docker compose up -d web face-service
```

## 서버에서 실제로 할 일

1. 서버 컴퓨터에 Docker 설치
2. 프로젝트 코드를 서버로 가져오기 (`git clone`)
3. `.env` 파일을 서버용 값으로 준비 (레포에는 절대 커밋하지 않음)
4. `docker compose up -d web face-service` 실행
5. 해당 서버 IP로 태블릿 등 클라이언트가 접속

## 카메라 권한 이슈 (HTTPS가 아닌 환경에서)

키오스크 페이지에서 카메라가 켜지지 않는 문제는, 브라우저가 보안 컨텍스트(HTTPS)가 아닌 주소를 신뢰하지 않아서 발생했다. Chrome 플래그에서 해당 origin을 예외로 등록해서 해결했다.

```
chrome://flags/#unsafely-treat-insecure-origin-as-secure
```

위 설정 화면에 서버 주소(포트 포함)를 추가해주면 카메라 권한 문제가 해결된다.

## 요구사항 정리

- 로그인했을 때 이름 뒤에 소속이 함께 표기되면 좋겠다.
- 얼굴 인식 후 이름이 뜨면서 "본인이 맞습니까? (y/n)"로 확인받고, 맞으면 출석 처리, 아니면 수정할 수 있게 한다.
- 최종 목표: 얼굴 인식 기능이 얼마나 정확한지, 어떤 오류가 왜 발생하는지 **데이터를 쌓아서 분석**하는 것. 단순히 "출석 체크가 되었다"에서 끝나지 않고, 인식 실패/오탑 사례를 축적해 개선 근거로 쓴다.

## 설계 원칙 메모 (`#에이전트 불가`)

- DB 연동은 PostgreSQL로 하고 Console/Web 양쪽에서 **CSV 없이 DB를 공유**한다.
- 공통 함수(`.py`)는 Console 프로그램과 Web에서 **그대로 재사용**할 수 있도록 만든다. → 같은 로직을 두 번 구현하지 않기 위한 설계 원칙.

## 추가 아이디어

- Slack API와 바로 연결되는 **공통 메시지 발송 함수**를 만들어서, 조별로 이 함수만 가져다 쓰면 바로 Slack 알림이 가도록 구조화하기로 논의.
- 평가(개별/팀) 기능: 퀴즈·게임·과제 등을 어떻게 반영할지, 근태관리 시스템도 함께 추가하기로 논의.

## 배운 점

- "여러 서버(컨테이너)가 켜진다"는 말이 곧 "여러 독립 프로그램이 있다"는 뜻은 아니다. 하나의 웹 애플리케이션 안에 여러 페이지/기능이 있을 뿐인 경우가 많다 — 시스템 구조를 먼저 컨테이너/서비스 단위로 파악하는 습관이 중요하다.
- 보안이 필요한 값(계정, 비밀번호, 서버 주소)은 애초에 메모/커밋 대상에서 분리해서 관리해야, 나중에 공개 저장소로 옮기거나 공유할 때 걱정할 일이 없다.
