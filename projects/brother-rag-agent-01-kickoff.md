## 배운 것

### RAG 검색 3단계

| 방식 | 한 줄 설명 | 강한 경우 |
|---|---|---|
| **Vector** | **뜻**으로 찾기 | 바꿔 말한 표현 |
| **BM25** | **글자**로 찾기 | 모델 코드, 오류 코드 |
| **Hybrid (RRF)** | 점수 대신 **순위**로 합치기. `1/(60+순위)`의 합 | 두 방식의 장점을 같이 |
| **Re-rank** | 후보를 질문과 함께 다시 읽어 순위를 재정렬 (cross-encoder) | 후보 안에서 정밀하게 고르기 |

- **Hit@k** = "검색이 정답을 상위 k개 안에 가져왔나"를 재는 **지표**.
- **Re-rank** = 순위를 바꾸는 **행동**. 지표와 행동은 다르다.

### 청킹과 필터

- 청킹: **제목 경로를 머리말로** 붙이고, 긴 절을 나눌 때만 오버랩을 쓴다.
- **모델 필터는 top-k 이전에** 걸어야 한다. 나중에 거르면 정답 후보가 이미 빠져 있을 수 있다.

### 거부 판정은 "시스템 상태 × 문항 유형"

| 문항 유형 | 시스템이 거부함 | 판정 |
|---|---|---|
| 정답형 | 거부 | **부당 거부** |
| 근거 없음 | 거부 | **올바른 거부** |
| (어느 쪽이든) | 오류 | **오류는 거부로 세지 않는다** |

### 평가 방식

- 공식 평가는 **Portal Runner가 우리 서버(`/agent/invoke`)를 호출**하는 방식이다.
- 그래서 **어떤 실패에도 HTTP 200 + 거부 형식**으로 응답해야 한다.

## 문제와 해결

| 문제 | 원인 | 해결 |
|---|---|---|
| pydantic 2.14.4를 설치했더니 서버가 안 뜸 (`DLL load failed`) | Windows 스마트 앱 컨트롤이 최신 `pydantic-core` DLL을 차단 | **2.14.2로 버전 고정** |
| Windows `curl`로 한글 질문을 보내면 오류 응답 | `curl`이 UTF-8이 아닌 인코딩으로 전송 | **Python `httpx`로 보내면 정상** |
| 60초를 넘기면 Runner가 "응답 없음"으로 처리 | Runner의 시간 제한 | 서버에 **내부 마감 50초**를 두고, 넘기면 거부 응답. 근거 없음 문항에서는 점수를 받을 수 있다 |

### 같은 날 작업 기록에서 더 정리한 것

- **DEV 평가기 `eval/run_eval.py`**: 공식 규칙대로 **60초 제한**을 두고, **연결 실패와 5xx만 1회 재시도**하며, **P50/P95**를 기록한다.
- 평가 서버는 틀려도 500을 내지 않고 **규격에 맞는 거부 응답**을 돌려줘야 한다. 그래서 오류를 단계별로 나눠 **HTTP 200 + 거부**로 바꿨다.
- **`redirect_slashes=False`**: `/health/`로 가는 리다이렉트도 평가기에서는 실패로 친다.
- `.gitignore`에는 PDF, 색인, `.env`를 제외했다.
- Windows `curl`은 한글을 **cp949**로 보내서 테스트가 깨졌다. `httpx`로 테스트하니 정상이었다.
- 최신 pydantic을 막은 이유는 주석으로 남겼다.

> 비슷한 문제를 전에도 만났다. 스마트 앱 컨트롤이 DLL을 막는 문제는 SQLAlchemy 때도 있었다. ([nextjs/02](../nextjs/02-react-components-state-and-fastapi-integration.md)의 문제 표 참고)
