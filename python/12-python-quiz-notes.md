# 자주 헷갈리는 개념 모음 (퀴즈 오답노트)

데일리 퀘스트/퀴즈를 풀면서 틀렸거나 헷갈렸던 개념들을 모아둔다.

## 리스트 vs 튜플

| | 리스트 | 튜플 |
|---|---|---|
| 기호 | `[]` | `()` |
| 가변성 | 가변 (생성 후 수정·추가·삭제 가능) | 불변 (생성 후 절대 수정 불가) |
| 특징 | 자유롭게 변경 | 메모리 소모가 적고 접근 속도가 빠름. 괄호를 생략하고 쉼표만으로도 튜플로 인식됨 |

## `all()`에 빈 리스트를 넘기면?

```python
print(all([]))  # True
```

`all()`은 내부에 `False`가 **하나도 없을 때** `True`를 반환한다. 빈 리스트에는 `False`가 존재하지 않으므로 `True`가 된다. 이 특성 때문에 실무에서는 "빈 데이터인지"를 먼저 확인하는 방어 로직이 필요하다.

## 별표 언패킹은 항상 리스트

```python
x, *rest = (1, 2, 3, 4)
print(rest)  # [2, 3, 4]  ← 원본이 튜플이어도 rest는 리스트
```

## f-string 포맷 스펙

```python
price = 12000
print(f"{price:>10,}")
```

- `>` : 오른쪽 정렬
- `10` : 폭(너비)
- `,` : 천 단위 구분 기호

`"12,000"`은 6글자이므로 10칸을 채우기 위해 앞에 공백 4칸이 추가되어 오른쪽 정렬된다.

디버깅용 조절자 `=`:

```python
score = 95
print(f"{score=}")  # score=95  ← 변수 이름과 값을 동시에 출력
```

## return vs yield

- `return`: 값을 반환하고 함수를 **완전히 종료**.
- `yield`: 값을 반환하면서도 함수의 실행 상태(지역 변수, 실행 위치)를 메모리에 **보존한 채 일시 정지**. 다음 `next()` 호출 시 그 지점부터 재개된다. 지연 평가(lazy evaluation)의 핵심 원리.

## 가비지 컬렉션 (Garbage Collection)

변수가 재할당되어 기존 데이터와의 연결이 끊기면, 이름표를 잃은 데이터는 **가비지 컬렉터**가 자동으로 메모리에서 정리한다. 개발자가 직접 메모리를 해제할 필요가 없다.

## 암묵적 형변환 (업캐스팅)

정수와 실수를 함께 연산하면, 파이썬은 데이터 손실을 막기 위해 정밀도가 더 높은 실수형으로 타입을 자동 통일한다. 이를 **업캐스팅**, 이러한 자동 변환을 **암묵적 형변환**이라 한다.

## `import` / `from ... import` / `as` 구분

- `import module` → 모듈 전체를 가져오며 `module.함수()`로 호출
- `from module import name` → 특정 함수/클래스만 가져와 `함수()`로 바로 호출 (모듈 이름 불필요)
- `import module as alias` → 별칭 부여

셋을 헷갈려서 "모듈 이름 없이 바로 호출하려면 어떤 키워드를 쓰는가?" 같은 문제에서 자주 틀렸다. 정답은 `from`이다.
