# 클래스와 객체

## 클래스는 설계도, 객체는 실제 값

> 클래스는 붕어빵틀, 객체는 붕어빵이다.

클래스는 속성(property)과 메서드를 정의한 **설계도**이고, 객체(object = instance)는 그 설계도를 바탕으로 메모리에 실제 할당된 값이다. 같은 클래스로 만든 객체들은 서로 독립된 메모리 공간을 가지므로, 한쪽을 변경해도 다른 쪽에는 영향을 주지 않는다.

```
클래스 설계 → 객체 생성 → 속성 저장 → 메서드 호출
```

## 기본 문법

```python
class Student:
    def __init__(self, name, score):
        self.name = name
        self.score = score

    def show_result(self):
        print(f"{self.name}님의 점수는 {self.score}입니다.")
        if self.score >= 60:
            print("합격입니다")
        else:
            print("불합격입니다")

student1 = Student("홍길동", 45)
student1.show_result()
```

- `__init__()`: 객체를 생성할 때 가장 먼저 호출되는 **초기화 함수(생성자, constructor)**. 객체 생성 시 필요한 초기값을 저장한다. (소멸 시 호출되는 함수가 아니라는 점에 주의)
- `self`: 현재 객체 자기 자신을 가리키는 참조. 메서드 안에서 `self.속성`으로 그 객체만의 값을 읽고 쓴다.

## 클래스 vs 인스턴스 vs 딕셔너리

| | 특징 |
|---|---|
| 딕셔너리 | `key: value`로 간단한 데이터를 담을 때 사용 |
| 클래스 | 데이터(속성)와 기능(메서드)이 함께, 반복적으로 필요할 때 사용 |

간단한 데이터 하나만 필요하면 딕셔너리로 충분하지만, "같은 모양의 데이터가 여러 개 있고 그 데이터에 대해 반복적으로 수행할 동작(메서드)"이 있다면 클래스를 고려한다.

## 객체를 리스트에 담아 반복 처리

```python
students = [Student("민수", 85), Student("지영", 92)]
for student in students:
    student.show_result()
```

## 자주 만나는 오류 체크 순서

1. `TypeError` — 인수 개수/타입이 맞는지 확인
2. `AttributeError` — 존재하지 않는 속성/메서드를 호출했는지 확인
3. `self` 누락 — 메서드 정의 시 첫 번째 매개변수로 `self`를 빠뜨렸는지 확인

AI에게 완성된 클래스 코드를 통째로 요구하기보다, **구조가 맞는지·오류 원인이 무엇인지**를 검토받는 방식으로 활용하는 것이 학습에 더 도움이 된다.
