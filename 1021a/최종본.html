오늘은 회원관리 페이지(헤더 + 검색 툴바 + 회원 카드 목록)를 만들면서 CSS 레이아웃(Flexbox, Grid, 반응형) 을 단계별로 익혔다. 이어서 사칙연산 계산기와 회원 데이터 관리를 만들며 JavaScript의 DOM 이벤트, 입력 검증, 함수·배열·객체를 정리했다. 코드는 fullstack-web-course의 phase06~phase09에 있다.

오늘의 한 줄 정리

  • 배치 방향이 한 줄이면 Flexbox, 행과 열의 격자이면 Grid다.
  • 반응형은 viewport 메타 태그 → 유연한 너비(% + max-width) → Mobile First 미디어 쿼리 순서로 쌓는다.
  • 입력값 검증은 빈 값 → 숫자인지 → 변환 → 0으로 나누기 순서가 중요하다.
  • map()은 요소를 변환하고, filter()는 조건에 맞는 요소만 골라낸다.

1. Flexbox: 한 줄(1차원) 배치

헤더, 툴바, 카드 안의 버튼처럼 가로 또는 세로 한 방향으로 요소를 배치할 때 쓴다.

.site-header {
    display: flex;
    justify-content: space-between; /* 제목은 왼쪽, 메뉴는 오른쪽 끝 */
    align-items: center;            /* 세로 가운데 정렬 */
}

.main-nav {
    display: flex;
    gap: 16px;                      /* 요소 사이 간격 */
}
속성 역할
display: flex 자식 요소들을 한 줄로 배치하는 컨테이너로 만듦
justify-content 주축(기본은 가로) 방향 정렬 (space-between = 양 끝으로 벌림)
align-items 교차축(기본은 세로) 방향 정렬
gap 자식 사이의 간격
flex: 1 남은 공간을 최대한 차지

검색창이 남은 공간을 차지하게 하기

.toolbar { display: flex; gap: 12px; align-items: center; }
.toolbar input { flex: 1; }   /* 버튼 두 개를 제외한 나머지 폭을 검색창이 다 차지 */

카드 안에서 세로로 쌓고, 버튼은 가로로 배치

.member-card   { display: flex; flex-direction: column; }  /* 제목·이메일·과정이 세로로 */
.card-actions  { display: flex; gap: 8px; margin-top: 16px; } /* 상세·수정 버튼은 가로로 */

2. Grid: 격자(2차원) 배치

회원 카드처럼 행과 열이 있는 목록은 Grid가 맞다.

.member-grid {
    display: grid;
    grid-template-columns: repeat(3, 1fr); /* 같은 너비의 3열 */
    gap: 20px;
}
  • 1fr은 "남은 공간을 1비율로 나눠 갖기"라는 뜻이다. repeat(3, 1fr)은 3등분이다.
  • Flexbox는 한 방향 배치, Grid는 행·열 격자 배치라고 구분하면 헷갈리지 않는다.

3. 반응형 웹: viewport, 유연한 컨테이너, Mobile First

viewport 메타 태그

<meta name="viewport" content="width=device-width, initial-scale=1.0">

이게 없으면 모바일 브라우저가 페이지를 데스크톱 너비로 가정하고 축소해서 보여준다. 반응형의 출발점이다.

유연한 컨테이너: width + max-width

.page-container {
    width: 90%;        /* 작은 화면에서는 화면의 90% */
    max-width: 1200px; /* 큰 화면에서는 1200px을 넘지 않음 */
    margin: 0 auto;    /* 가운데 정렬 */
}

Mobile First + 미디어 쿼리

작은 화면(모바일) 스타일을 기본값으로 먼저 쓰고, 화면이 넓어질 때만 min-width 미디어 쿼리로 덮어쓴다.

/* 기본 (모바일): 1열, 헤더는 세로 배치 */
.member-grid  { display: grid; grid-template-columns: 1fr; gap: 16px; }
.page-header  { display: flex; flex-direction: column; }

/* 태블릿 (768px 이상): 2열, 헤더는 가로 배치 */
@media (min-width: 768px) {
    .member-grid { grid-template-columns: repeat(2, 1fr); }
    .page-header { flex-direction: row; justify-content: space-between; align-items: center; }
}

/* 데스크톱 (1024px 이상): 3열 */
@media (min-width: 1024px) {
    .member-grid { grid-template-columns: repeat(3, 1fr); }
}

흐름은 1열 → 2열 → 3열, 세로 헤더 → 가로 헤더다.

4. 화면 밖으로 넘치는 것 막기

input, select, textarea { width: 100%; box-sizing: border-box; } /* padding이 너비에 포함되어 가로 스크롤 방지 */
img { max-width: 100%; height: auto; }                           /* 이미지가 컨테이너보다 커지지 않게, 비율 유지 */
  • box-sizing: border-box가 없으면 width: 100% + padding이 합쳐져 부모보다 커지면서 가로 스크롤이 생긴다.
  • 폼 요소와 이미지는 이렇게 따로 넘침을 막아 줘야 한다.

5. JavaScript: DOM 요소 가져오기와 이벤트 등록

사칙연산 계산기(Chapter 08)에서 가장 먼저 한 일은 HTML 요소를 가져와 클릭 이벤트를 붙이는 것이다.

const num1Input = document.getElementById('num1');
const calcBtn   = document.getElementById('calcBtn');

calcBtn.addEventListener('click', function () {
    // 버튼이 클릭될 때 실행할 코드
});
  • document.getElementById('id'): HTML의 id로 요소를 찾는다.
  • addEventListener('click', 함수): 클릭 같은 이벤트가 일어났을 때 실행할 함수를 등록한다.
  • <script src="app.js">는 요소들이 만들어진 </body> 직전에 두어야, 스크립트가 실행될 때 요소를 찾을 수 있다.

6. 입력값 검증은 순서가 중요하다

const rawNum1 = num1Input.value.trim();   // 입력값은 항상 "문자열"

if (rawNum1 === '' || rawNum2 === '') { alert('두 숫자를 모두 입력해 주세요.'); return; }   // 1. 비었는지
if (isNaN(rawNum1) || isNaN(rawNum2)) { alert('올바른 숫자를 입력해 주세요.'); return; }    // 2. 숫자인지
const num1 = Number(rawNum1);                                                              // 3. 변환
if (operator === '/' && num2 === 0)   { alert('0으로 나눌 수 없습니다.'); return; }         // 4. 0으로 나누기
  • input.value는 숫자를 입력해도 문자열이라, 계산 전에 Number()로 바꿔야 한다. ("1" + "2"는 "12")
  • 빈 값 검사를 isNaN보다 먼저 해야 한다. isNaN('')은 false다. 빈 문자열이 Number('')에서 0으로 바뀌기 때문이다. 그래서 isNaN만으로는 빈 입력을 걸러내지 못한다.
  • .trim()으로 앞뒤 공백을 제거해야 " " 같은 입력도 빈 값으로 처리된다.
  • return으로 검증에 실패하면 함수를 즉시 끝낸다. Python 예외 처리에서 "정상 입력만 테스트하면 안 된다"고 했던 것과 같은 생각이다.

7. 연산자 분기: switch

switch (operator) {
    case '+': result = num1 + num2; break;
    case '-': result = num1 - num2; break;
    case '*': result = num1 * num2; break;
    case '/': result = num1 / num2; break;
}
alert(`결과: ${num1} ${operator} ${num2} = ${result}`);
  • break가 없으면 아래 case까지 계속 실행된다.
  • 백틱(`)과 ${}를 쓰는 템플릿 리터럴은 Python의 f-string과 같은 역할이다.

8. 함수, 배열, 객체

회원 데이터 관리(Chapter 09)에서는 함수와 배열, 객체를 함께 썼다.

function greet(name, age) {
    return `안녕하세요, ${age}세 ${name}님! 환영합니다.`;   // 값을 반환
}

let users = [
    { id: 1, name: '김철수', age: 25, isActive: true },
    { id: 2, name: '이영희', age: 30, isActive: false },
];

배열 안에 객체를 담는 구조는 Python의 리스트 안의 딕셔너리와 같다. 한 행이 객체 하나인 표 형태 데이터다.

9. map()과 filter()

메서드 하는 일 결과
map(fn) 각 요소를 변환해서 같은 길이의 새 배열
filter(fn) 조건이 true인 요소만 골라서 길이가 줄어들 수 있는 새 배열 
// map: 모든 회원을 <li> 문자열로 변환
const userHtmls = users.map(user => `<li>이름: ${user.name} / 나이: ${user.age}세</li>`);
userListEl.innerHTML = userHtmls.join('');   // 배열을 하나의 문자열로 합침

// filter: isActive가 true인 회원만
const activeUsers = users.filter(user => user.isActive);
  • 둘 다 원본 배열을 바꾸지 않고 새 배열을 반환한다.
  • map 결과는 배열이라 innerHTML에 넣기 전에 .join('')으로 문자열로 합쳐야 한다. 안 하면 쉼표가 같이 찍힌다.
  • Next.js 퀴즈에서 상품 목록을 .map()으로 카드 컴포넌트로 바꿨던 것이 같은 개념이다.

10. 배열에 추가하고 화면 다시 그리기

const lastId = users.length > 0 ? users[users.length - 1].id : 0;   // 삼항 연산자: 비었으면 0부터
const newUser = { id: lastId + 1, name: userName, age: userAge, isActive: userAge < 50 };
users.push(newUser);   // 배열 끝에 추가
renderUsers();         // 화면을 그리는 코드를 함수로 만들어 두었기 때문에 다시 호출만 하면 된다

핵심 패턴은 데이터(배열)를 바꾸고 → 그리는 함수를 다시 호출하는 것이다. 화면을 직접 고치는 대신 데이터와 렌더링을 분리하면 추가/삭제가 쉬워진다.

11. 짚고 넘어간 점

  • !userAge로 나이를 검증하면 0도 "입력 없음"이 된다. 0은 falsy라서다. 빈 값 여부와 숫자 여부는 따로 검사하는 편이 정확하다. (Python의 Falsy 값과 같은 원리)
  • innerHTML에 사용자 입력을 그대로 넣으면 위험하다. 이름 칸에 <script>나 HTML 태그를 넣으면 그대로 해석될 수 있다(XSS). 사용자 입력은 textContent로 넣는 것이 안전하다. 이번 실습은 학습용이라 innerHTML을 썼지만 실제 서비스에서는 피해야 한다.
  • HTML 오타는 화면에 그대로 보인다. Chapter 08 index.html의 </select>s처럼 태그 뒤에 글자 하나가 붙으면 에러 없이 화면에 s가 찍힌다. HTML은 문법 오류를 알려주지 않고 조용히 렌더링하므로 브라우저로 직접 확인해야 한다.
