오늘은 SQL 서브쿼리(Subquery) 를 정리했다. 서브쿼리가 어디에 놓이느냐(WHERE절, FROM절, SELECT절)에 따라 이름과 규칙이 달라져서, 위치별로 나눠 두고 헷갈렸던 부분을 오답노트로 남겨 둔다.

오늘의 한 줄 정리

  • 서브쿼리는 괄호 () 로 감싼 또 하나의 SELECT 이고, 외부 쿼리보다 먼저 실행된다.
  • WHERE절에서 서브쿼리가 여러 행을 돌려주면 = 대신 IN 을 쓴다.
  • NOT IN은 결과에 NULL이 섞이면 조용히 빈 결과를 낼 수 있어서 NOT EXISTS 를 권장한다.
  • FROM절의 서브쿼리는 인라인 뷰(별칭 필수), SELECT절의 서브쿼리는 스칼라 서브쿼리(값 하나만 반환)다.

1. 서브쿼리란

하나의 SQL 쿼리 안에 포함된 또 다른 SELECT 쿼리다. 괄호 () 로 감싸며(중괄호가 아니다), 외부 쿼리보다 먼저 실행되어 그 결과를 외부 쿼리에 전달한다.

SELECT name
FROM members
WHERE member_id IN (
    SELECT member_id FROM loans WHERE returned = false  -- 서브쿼리
);

JOIN은 테이블을 합치는 것이고, 서브쿼리와는 다른 개념이다.

2. WHERE절에서 여러 행을 반환할 때: = 대신 IN

서브쿼리가 여러 행(값) 을 반환하면 단일 값 비교 연산자인 =을 쓸 수 없다. 목록 중 하나라도 일치하면 참이 되는 IN을 사용한다. 반대로 목록에 포함되지 않는 경우는 NOT IN을 사용한다.

-- 서브쿼리가 여러 행을 반환하면 에러
WHERE member_id = (SELECT member_id FROM loans WHERE ...)

-- 올바른 방식
WHERE member_id IN (SELECT member_id FROM loans WHERE ...)

3. NOT IN보다 NOT EXISTS를 권장하는 이유: NULL 함정

서브쿼리 결과에 NULL이 하나라도 포함되면, NOT IN은 전체 결과가 빈 값으로 나올 수 있다. NOT EXISTS는 NULL에 영향을 받지 않기 때문에 더 안전하다.

-- NULL이 섞여 있으면 예상과 다르게 빈 결과가 나올 위험
WHERE member_id NOT IN (SELECT member_id FROM loans)

-- 더 안전한 방식
WHERE NOT EXISTS (
    SELECT 1 FROM loans WHERE loans.member_id = members.member_id
)

NOT IN이 문법 오류를 내는 것은 아니다. 조용히 의도와 다른(잘못된) 결과를 내는 것이 더 위험한 지점이다. NOT EXISTS는 WHERE절에서 사용하며 FROM절 전용은 아니다.

4. FROM절의 서브쿼리: 인라인 뷰

FROM절에 위치해서 마치 하나의 임시 테이블처럼 사용되는 서브쿼리를 인라인 뷰(Inline View) 라고 부른다. 데이터베이스에 저장되지 않는 일회성 임시 테이블처럼 동작하며, 반드시 별칭(alias)을 붙여야 한다.

SELECT category, avg_price
FROM (
    SELECT category, AVG(price) AS avg_price
    FROM products
    GROUP BY category
) AS category_summary   -- 별칭 필수
WHERE avg_price > 10000;

5. SELECT절의 서브쿼리: 스칼라 서브쿼리

SELECT절에 위치하는 서브쿼리로, 반드시 하나의 행, 하나의 열(단일 값)만 반환해야 한다. 여러 행을 반환하면 "첫 번째 행만 자동으로 사용"되는 것이 아니라 PostgreSQL에서 오류가 발생한다.

SELECT
    name,
    (SELECT COUNT(*) FROM loans WHERE loans.member_id = members.member_id) AS loan_count
FROM members;

이렇게 외부 쿼리의 각 행마다 값이 달라지도록, 외부 테이블의 컬럼을 참조하는 서브쿼리를 상관 서브쿼리(Correlated Subquery) 라고 한다.

6. 오답노트: 헷갈리기 쉬운 지점 정리

원본 노트에서 바로잡아 둔 내용을 한 번에 모아 둔다. 시험에서 함정이 되기 쉬운 문장들이다.

헷갈리기 쉬운 생각 바로잡은 내용
서브쿼리는 중괄호 {} 로 감싼다 괄호 () 로 감싼다
JOIN도 서브쿼리의 한 종류다 JOIN은 테이블을 합치는 것으로, 서브쿼리와 다른 개념이다
여러 행을 반환해도 = 로 비교할 수 있다 여러 행이면 = 은 에러. IN 을 쓴다
NOT IN은 문법 오류를 낸다 문법 오류가 아니라 NULL이 섞이면 조용히 잘못된(빈) 결과를 낸다
NOT EXISTS는 FROM절 전용이다 WHERE절에서 사용한다
스칼라 서브쿼리가 여러 행을 반환하면 첫 번째 행만 쓴다 자동으로 첫 행을 쓰지 않고 PostgreSQL에서 오류가 발생한다
인라인 뷰는 별칭 없이도 된다 별칭(alias)이 필수다

오늘의 핵심 정리

위치 이름 핵심 규칙
WHERE절 (일반 서브쿼리) 여러 행이면 IN / NOT IN, NULL이 걱정되면 NOT EXISTS
FROM절 인라인 뷰 임시 테이블처럼 사용, 별칭 필수
SELECT절 스칼라 서브쿼리 하나의 행, 하나의 열만 반환
