# 타이타닉 데이터로 보는 EDA 전체 사이클

## AI와 함께 데이터 분석 한 사이클 완주하기

타이타닉 생존자 데이터를 가지고 데이터 로딩부터 서비스 배포까지 전체 흐름을 한 번 완주해보는 실습.

```
데이터 준비
  → 데이터 이해
  → 전처리
  → 시각화와 EDA
  → Feature 설계
  → 학습/테스트 분리
  → Baseline 모델
  → 모델 평가
  → 추가 모델 비교
  → 최종 모델
  → 저장과 신규 예측
  → Streamlit 서비스
```

## 머신러닝 학습 방식 3가지

| 학습 방식 | 특징 |
|---|---|
| 지도학습 (Supervised) | 정답(label)이 있는 데이터로 학습 |
| 비지도학습 (Unsupervised) | 정답 없이 데이터의 구조/패턴을 찾음 |
| 강화학습 (Reinforcement) | 보상(reward)을 기준으로 행동을 학습 |

타이타닉 생존 예측은 생존 여부(정답)가 있으므로 **지도학습** 문제다.

## 이 사이클에서 실제로 다룬 것들

- 결측치 처리: 숫자형(`age`)은 평균, 범주형(`embarked`)은 최빈값으로 채움 → [03-missing-values-outliers-typeconversion.md](03-missing-values-outliers-typeconversion.md)
- 이상치 확인: `fare`의 박스 플롯에서 최댓값 512달러 확인
- 그룹별 통계: `groupby`로 생존율을 성별/객실등급별로 비교

## Feature가 너무 많으면 오히려 성능이 떨어진다

컬럼(피처)이 많으면 오히려 모델의 정확도가 떨어질 수 있다. 분석과 무관하거나 중복된 정보를 담은 컬럼을 무작정 다 넣는 것이 아니라, **예측에 실제로 의미 있는 컬럼을 선별**하는 과정(Feature 설계)이 중요하다는 것을 체감했다.
