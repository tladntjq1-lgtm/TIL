오늘부터 Brother RAG Agent 프로젝트가 시작됐다. 발제 문서를 분석하고, 팀 역할과 5일 계획을 정하고, 팀 저장소를 세팅하고, FastAPI 서버 골격까지 만들었다. 이 글에는 오늘 한 일과 함께 새로 배운 검색 방식, 거부 판정 기준, 평가 방식, 그리고 부딪힌 문제와 해결을 정리해 둔다. 앞서 공부한 RAG 파이프라인, 임베딩과 코사인 유사도, 청킹과 텍스트 분할기, FastAPI 기초가 이 프로젝트에서 처음 한데 묶였다.

오늘의 한 줄 정리

  • 이 프로젝트는 Brother 프린터 10개 모델에 대한 질문에 공식 PDF에서 근거를 찾아 페이지까지 인용하는 RAG Agent를 만드는 일이다.
  • 검색은 Vector(뜻), BM25(글자), Hybrid RRF(순위 합치기), Re-rank(다시 읽어 재정렬) 로 나눠 이해한다.
  • 거부 판정은 시스템 상태 × 문항 유형으로 정해지고, 오류는 거부로 세지 않는다.
  • 공식 평가는 Portal Runner가 우리 서버를 호출하는 방식이라 어떤 실패에도 HTTP 200 + 거부 형식으로 응답해야 한다.

1. 오늘 한 일과 프로젝트 소개

발제 문서 분석. Brother 프린터 10개 모델에 대한 질문에, 공식 PDF 2권(잉크젯 466쪽, 레이저 633쪽)에서 해당 모델의 근거를 찾아 페이지까지 인용하는 RAG Agent를 만든다. 비공개 100문항(정답형 90 + 근거 없음 10)으로 평가한다.

팀 역할 분담과 5일 계획 발표 자료 작성. 3인 팀이고 역할은 A 데이터, B 검색·생성, C 서버·평가로 나눴다. 나는 C를 맡았다.

그 밖에 오늘 한 일은 다음과 같다.

  • 유사 오픈소스를 조사하고 비교했다. 한국어 하이브리드 검색 튜토리얼, citerag, Multi-Meta-RAG 등을 봤다.
  • 팀 통합 레퍼런스 중 "평가·재현" 파트의 분석 문서를 썼다.
  • #22 팀 저장소 초기 세팅: .gitignore, requirements 버전 고정, README, 협업 규칙을 정리했다.
  • #2 인터페이스 초안(PR #32) 리뷰: API 응답과 로그 형식에 의견 13개를 남겼고 전부 반영됐다.
  • #23 FastAPI 서버 골격: GET /health, POST /agent/invoke를 만들었고 테스트 11개가 통과했다.

2. RAG 검색 방식 비교: Vector, BM25, Hybrid, Re-rank

방식 한 줄 설명 강한 경우
Vector 뜻으로 찾기 바꿔 말한 표현
BM25 글자로 찾기 모델 코드, 오류 코드
Hybrid (RRF) 점수 대신 순위로 합치기. 1/(60+순위)의 합 두 방식의 장점을 같이
Re-rank 후보를 질문과 함께 다시 읽어 순위를 재정렬 (cross-encoder) 후보 안에서 정밀하게 고르기
  • Hit@k는 "검색이 정답을 상위 k개 안에 가져왔나"를 재는 지표다.
  • Re-rank는 순위를 바꾸는 행동이다. 지표와 행동은 다르다.

3. 청킹과 필터

  • 청킹은 제목 경로를 머리말로 붙이고, 긴 절을 나눌 때만 오버랩을 쓴다.
  • 모델 필터는 top-k 이전에 걸어야 한다. 나중에 거르면 정답 후보가 이미 빠져 있을 수 있다.

4. 거부 판정은 시스템 상태 × 문항 유형

같은 "거부"라도 문항이 어떤 유형인지에 따라 판정이 달라진다.

문항 유형 시스템이 거부함 판정
정답형 거부 부당 거부
근거 없음 거부 올바른 거부
(어느 쪽이든) 오류 오류는 거부로 세지 않는다

5. 평가 방식과 60초 제한

  • 공식 평가는 Portal Runner가 우리 서버(/agent/invoke)를 호출하는 방식이다.
  • 그래서 어떤 실패에도 HTTP 200 + 거부 형식으로 응답해야 한다.
  • Runner에는 60초 시간 제한이 있어서, 60초를 넘기면 "응답 없음"으로 처리된다. 이를 막으려고 서버에 내부 마감 50초를 두고, 넘기면 거부 응답을 돌려준다. 근거 없음 문항에서는 이 거부 응답으로 점수를 받을 수 있다.

6. 문제와 해결

문제 원인 해결
pydantic 2.14.4를 설치했더니 서버가 안 뜸 (DLL load failed) Windows 스마트 앱 컨트롤이 최신 pydantic-core DLL을 차단 2.14.2로 버전 고정
Windows curl로 한글 질문을 보내면 오류 응답 curl이 UTF-8이 아닌 인코딩으로 전송 Python httpx로 보내면 정상
60초를 넘기면 Runner가 "응답 없음"으로 처리 Runner의 시간 제한 서버에 내부 마감 50초를 두고, 넘기면 거부 응답. 근거 없음 문항에서는 점수를 받을 수 있다

비슷한 문제를 전에도 만났다. 스마트 앱 컨트롤이 DLL을 막는 문제는 SQLAlchemy 때도 있었다. (이전 Next.js 글의 문제 표 참고)
