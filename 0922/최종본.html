오늘은 AI/ML 수업에서 어텐션 메커니즘, 프롬프팅 기법, 경사하강법과 과적합을 배웠다. 문제를 풀다가 헷갈렸던 부분이 몇 개 있어서, 마지막에 오답노트로 따로 모아 두었다.

오늘의 한 줄 정리

  • Seq2Seq는 문장 전체를 고정 크기 벡터 하나에 압축하다 병목이 생기고, 어텐션은 이를 해결하려고 나왔다.
  • 어텐션은 Q·K 내적으로 점수를 구하고 → Softmax로 정규화한다.
  • 예시를 프롬프트에 넣고 가중치는 그대로면 Few-shot, 가중치를 바꾸면 파인튜닝이다.
  • 학습률이 너무 크면 오버슈팅이고, 과적합은 별개의 문제다.

1. Seq2Seq의 병목 현상

기존 Seq2Seq 모델은 입력 문장의 길이와 상관없이, 전체 문맥을 고정된 크기의 컨텍스트 벡터 하나에 압축해서 디코더로 전달한다. 문장이 길어지면 이 하나의 벡터에 방대한 정보를 억지로 눌러 담다가 문장 앞부분의 정보가 유실되는 구조적 한계가 있는데, 이를 병목 현상(Bottleneck) 이라 부른다.

어텐션 메커니즘은 이 병목 현상을 해결하기 위해 등장했다. 인코더의 마지막 벡터 하나에만 의존하지 않고, 인코더의 모든 시점(단어)의 벡터를 디코더가 필요할 때마다 다시 참고할 수 있게 만든 것이다.

2. 어텐션 연산 2단계

  1. 유사도 점수 계산: 디코더의 현재 상태 벡터(Q, Query)와 인코더의 각 단어 벡터(K, Key)를 내적(dot product)하여 유사도 점수(Score)를 구한다.
  2. 정규화: 이 점수에 소프트맥스(Softmax) 함수를 적용해 총합이 1이 되는 확률 분포(가중치)로 변환한다.
Score = Q · K
Attention Weight = softmax(Score)
  • 왜 소프트맥스인가: 시그모이드, ReLU, tanh는 각각 이진 분류, 은닉층 활성화, 범위 압축 등 다른 목적의 활성화 함수이며, "여러 값의 총합을 1로 만드는 정규화" 역할은 하지 못한다. 소프트맥스만이 여러 유사도 점수를 "각 단어에 얼마나 집중할지"를 나타내는 확률 분포로 바꿔 준다.
  • 이렇게 구한 가중치를 인코더의 각 단어 벡터(V, Value)에 곱해서 더하면, 디코더가 현재 시점에 어떤 입력 단어에 더 집중해야 하는지를 반영한 벡터를 얻는다.

3. Few-shot과 프롬프팅 기법 비교

고객 문의 메일을 특정 형식으로 분류시키고 싶을 때, 모델에게 원하는 패턴을 학습시키는 방법에는 비용과 방식이 다른 여러 옵션이 있다.

Few-shot Prompting은 지시문과 함께 2개 이상의 입력-출력 예시 쌍을 프롬프트에 직접 포함시켜, 모델이 원하는 출력 패턴을 즉시 인지하도록 만드는 기법이다. 모델의 가중치를 바꾸지 않고, 문맥 내 학습(In-Context Learning) 을 통해 그 자리에서 패턴을 파악하게 만든다.

지시문: 아래 문의 메일을 [문의/불만/칭찬] 중 하나로 분류해줘.

예시1) 입력: "배송이 너무 늦어요" → 출력: 불만
예시2) 입력: "환불은 어떻게 하나요?" → 출력: 문의

입력: "상품 정말 만족스러워요!" → 출력: ?
기법 방식 비용
Zero-shot 예시 없이 지시문만으로 바로 요청 가장 저렴
Few-shot 지시문 + 예시 2개 이상을 프롬프트에 포함 저렴, 즉시 적용
Fine-tuning (파인튜닝) 모델 가중치 자체를 재학습으로 변경 고비용, 시간 소요
Context Engineering 프롬프트를 넘어서 모델에게 주어지는 전체 정보 환경(문서, 도구, 대화 기록 등)을 설계 상황에 따라 다름
  • 예시가 전혀 없으면 Zero-shot, 예시를 프롬프트에 넣으면 Few-shot이다. 둘 다 모델 가중치는 그대로다.
  • 파인튜닝은 프롬프트 기법이 아니라 모델 자체를 바꾸는 것이라 훨씬 무겁고 비용이 크다.
  • 컨텍스트 엔지니어링은 단순히 프롬프트 문장을 잘 쓰는 것을 넘어, 모델이 참고할 전체 정보(검색 결과, 도구 목록, 이전 대화 등)를 어떻게 구성하느냐의 문제라서 "예시 2개를 넣는 것"과는 층위가 다르다.

4. 경사하강법과 학습률

경사하강법의 가중치 업데이트 공식은 다음과 같다.

w_new = w_old - α · (∂J/∂w)
  • w : 가중치
  • α (알파) : 학습률(learning rate), 한 번에 얼마나 이동할지 정하는 보폭
  • ∂J/∂w : 손실 함수 J를 가중치로 미분한 기울기(gradient)

학습률(보폭)을 지나치게 크게 설정하면, 최저점(최소 손실 지점)을 지나쳐 버리는 오버슈팅(Overshooting) 이 발생한다. 그 결과 오차가 줄어들지 않고 오히려 발산할 수 있다.

반대로 학습률이 너무 작으면 다음과 같은 문제가 생긴다.

  • 학습 속도가 지나치게 느려진다.
  • 로컬 미니멈(local minimum, 진짜 최저점이 아닌 곳)에 갇히기 쉽다.

5. 과적합과 Train / Valid / Test 분리

과적합(Overfitting) 은 모델이 훈련 데이터의 일반적인 패턴이 아니라 정답을 통째로 외워버려서, 한 번도 본 적 없는 새로운 데이터에서는 성능이 떨어지는 현상이다.

방지하려면 전체 데이터를 Train(학습) / Valid(검증) / Test(최종 평가)로 나눈다.

  • Train: 모델이 실제로 학습에 사용하는 데이터
  • Valid(검증): 학습 중간에 성능을 점검하며 과적합 여부를 판단하는 데이터 (모델이 직접 학습하지는 않음)
  • Test: 모든 학습이 끝난 뒤 최종 성능을 평가하는, 학습 과정에 전혀 사용되지 않은 데이터

이렇게 나눠야 "학습에 쓴 데이터에서만 잘하는지"와 "본 적 없는 데이터에서도 잘하는지"를 구분해서 확인할 수 있고, 과적합 여부를 제대로 판단할 수 있다.

6. 오늘의 오답노트

병목 현상과 정보 유출

  • "정보 유출"이 아니라 "병목 현상(Bottleneck)" 이 정확한 용어다. 정보가 새어나가는(leak) 게 아니라, 압축 과정에서 소실(loss)되는 것이라는 뉘앙스 차이를 기억한다.

어텐션 연산 순서

  • Q·K 내적 → 유사도 점수 → Softmax → 가중치, 이 순서를 헷갈리지 않는다. Softmax는 점수를 구한 다음 단계다.

Few-shot과 파인튜닝

  • "예시를 프롬프트에 넣어서 패턴을 즉시 학습시킨다"는 설명을 보고 반사적으로 "파인튜닝"을 골랐는데, 파인튜닝은 모델 가중치를 바꾸는 것이라 예시 프롬프트와는 전혀 다른 접근이다. "즉시" + "가중치 변경 없음" 키워드가 나오면 Few-shot을 먼저 떠올린다.

학습률과 과적합

  • 학습률이 너무 크면 "과적합"이 생긴다고 착각하기 쉽다. 하지만 과적합은 학습률 문제가 아니라, 데이터 분할(train/valid/test)이 없거나 모델이 데이터를 암기할 만큼 충분히(또는 과도하게) 학습된 경우에 생기는 별개의 문제다. 학습률이 너무 크면 생기는 문제는 오버슈팅과 발산이다.
