오늘의 한 줄 정리

  • /agent/invoke 오류는 DB 주소 값 오류 → 비밀번호 인증 실패 → OpenAI 401 순서로 3번 이어졌고, 서버가 DB를 먼저 읽고 OpenAI를 부른다는 호출 순서가 원인을 가르는 단서가 됐다.

2. main 머지 = 자동 배포 구조

유료 Vercel 팀으로 옮기면서 main 브랜치에 머지하면 곧바로 배포되는 구조를 만들었다. 여기에 한 가지 설계가 더해졌다.

  • BM25 색인을 Supabase 표에 올린다.
  • 서버가 처음 켜질 때 그 색인을 받아 온다.

색인은 DB 표에 올려 두고, 서버는 시작할 때 그것을 가져다 쓴다. 나중에 색인을 바꿀 때도 새 색인을 Supabase에 올리고 INDEX_VERSION을 교체한다. (다음에 할 일 참고)

3. 배포 오류를 구분하는 순서

배포가 실패하거나 서버가 이상하게 동작할 때 가장 먼저 한 일은 같은 커밋을 같은 설정으로 로컬에서 돌려 보는 것이다. 그래야 코드 문제인지 환경 문제인지 나뉜다.

개념 이해용: 로컬에서도 같은 오류가 나면 코드 쪽을, 로컬에서는 정상인데 배포에서만 나면 환경 쪽을 의심한다는 뜻으로 정리했다.

이번에 만난 빌드 실패 2건

증상 해결
프리셋이 Other라서 함수를 못 찾았다 framework: fastapi로 지정
루트 requirements(streamlit 포함)를 설치해서 549MB가 됐다 서버용 패키지만 설치

배포 과정에서 얻은 규칙들

  • 로그가 잘리면 원인을 못 본다. 오류만 따로 남기되 비밀값은 가린다.
  • 환경변수는 바꾸면 Redeploy를 해야 적용된다.
  • Vercel 권한: Developer 역할은 Production 환경변수와 프로덕션 CLI 배포가 안 된다. 관리자(튜터)에게 정확히 무엇을 요청할지 목록으로 정리해서 전달하면 빠르다.

4. /agent/invoke 오류 3연속과 호출 순서

배포한 뒤 /agent/invoke가 3번 연속으로 다른 오류를 냈다.

순서 원인
1 DB 주소 값 오류
2 비밀번호 인증 실패
3 OpenAI 401

로그로 하나씩 원인을 짚어서 튜터에게 정확히 요청했고, 그렇게 해결했다.

여기서 도움이 된 것이 호출 순서다. 서버는 DB를 먼저 읽고 OpenAI를 부른다. 이 순서를 이용해서, OpenAI 오류가 남아 있는 상태에서도 DB 쪽이 해결된 것을 따로 확인할 수 있었다.

개념 이해용: 호출 순서가 DB, OpenAI 순이므로 OpenAI 오류가 보이면 DB 단계는 이미 지나간 것으로 읽을 수 있다.

DB 주소를 전달하다가 얻은 규칙도 하나 있다. 비밀번호가 든 DB 주소를 메신저로 보내면 링크로 바뀌면서 % 인코딩이 달라질 수 있다. 그래서 파일로 전달한다.
