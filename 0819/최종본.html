오늘부터 데이터베이스와 SQL을 배우기 시작했다. 먼저 SQL이 실행되는 순서와 명령어 분류(DDL, DML, DCL, TCL) 를 익히고, 이어서 ERD로 테이블 사이의 관계(1:N, N:M) 를 표현하는 방법을 정리했다. 헷갈리기 쉬운 부분은 따로 표시해 두었다.

오늘의 한 줄 정리

  • SQL은 작성 순서와 실행 순서가 다르다. WHERE는 SELECT보다 먼저 실행되므로 SELECT의 별칭을 쓸 수 없다.
  • 명령어는 DDL(구조), DML(데이터), DCL(권한), TCL(트랜잭션) 로 나뉜다. INSERT INTO는 DML이다.
  • N:M 관계는 직접 표현할 수 없어서 중간 테이블을 만들어 두 개의 1:N 관계로 나눈다.

1. AI 시대에도 데이터베이스를 배워야 하는 이유

  • AI가 SQL을 만들어 줘도, 실행에 성공하는 SQL과 요구사항에 맞는 결과를 주는 SQL은 다르다.
  • 잘못된 데이터나 조회 기준은 결과에 직접적인 영향을 준다.
  • 현실의 업무를 데이터와 관계로 표현하려면, 파일, 스프레드시트, DBMS 중 어떤 방식이 적절한지 판단하는 기준이 필요하다.
  • AI가 만든 데이터 구조와 SQL 결과라도 사람이 직접 확인해야 하는 항목이 있다.

2. SQL 작성 순서 vs 실행 순서

이 둘이 다르다는 것이 핵심 개념이다.

  • 작성 순서: SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY
  • 실행 순서: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY

WHERE는 SELECT보다 먼저 실행되기 때문에, SELECT에서 정의한 별칭(alias)을 WHERE절에서 사용할 수 없다.

-- 아래처럼 쓰면 에러가 난다 (total은 SELECT에서 만든 별칭)
SELECT price * quantity AS total
FROM orders
WHERE total > 10000;   -- 오류: WHERE가 SELECT보다 먼저 실행되므로 total을 모른다

3. SQL 명령어 분류: DDL, DML, DCL, TCL

분류 역할 대표 명령어
DDL (Data Definition Language) 데이터베이스 구조(테이블, 스키마)를 정의, 변경, 삭제 CREATE, ALTER, DROP
DML (Data Manipulation Language) 데이터 자체를 조작 SELECT, INSERT, UPDATE, DELETE
DCL (Data Control Language) 권한을 제어 GRANT, REVOKE
TCL (Transaction Control Language) 트랜잭션을 제어 COMMIT, ROLLBACK

INSERT INTO는 데이터를 조작하는 DML이다. 구조를 정의하는 DDL이 아니라는 점을 헷갈리기 쉽다.

4. PRIMARY KEY

테이블 안에서 각 행(Row)을 유일하게 식별하는 열로, 두 가지 핵심 규칙을 가진다.

  • 중복 값을 가질 수 없다.
  • NULL 값을 가질 수 없다.

5. 타입이 맞지 않는 값을 넣으면?

INT 타입 열에 문자열('홍길동')을 넣으려 하면 invalid input syntax for type integer 같은 오류가 발생하며 해당 INSERT가 거부된다. 데이터베이스가 잘못된 타입의 데이터가 저장되는 것을 자동으로 막아 준다.

6. INSERT INTO에서 열 이름을 명시하는 이유

INSERT INTO members (name, email, age)
VALUES ('홍길동', 'hong@example.com', 25);

열 이름을 명시하면 열 순서가 바뀌거나 일부 열만 입력해도 오류 없이 안전하게 동작한다. VALUES 절은 쉼표로 구분해 여러 행을 한 번에 입력할 수도 있다.

7. 관계형 데이터베이스의 기본 구조: 테이블

관계형 데이터베이스(RDBMS)는 데이터를 테이블이라는 2차원 구조에 저장하며, 행(Row)과 열(Column)로 구성된다. 엑셀 같은 스프레드시트와 비슷한 형태다.

8. 까마귀발 표기법으로 1:N 관계 읽기

테이블 사이의 관계는 ERD에서 까마귀발 표기법(Crow's Foot Notation)으로 표현한다.

회원 ||──O< 주문
  • ||: 정확히 1개(필수)
  • O<: 0개 이상

즉 회원 한 명은 0개 이상의 주문을 가질 수 있고, 주문 하나는 반드시 한 명의 회원과 연결된다. 이것이 1:N 관계다.

9. N:M 관계는 중간 테이블로 풀어야 한다

학생과 강의처럼, 한 학생이 여러 강의를 들을 수 있고 하나의 강의에도 여러 학생이 있는 N:M 관계는 데이터베이스에서 직접 표현할 수 없다. 반드시 중간 테이블(Junction Table) 을 만들어 두 개의 1:N 관계로 분리해야 한다.

학생 (1) ── (N) 수강 (N) ── (1) 강의
  • 학생 : 수강 = 1 : N
  • 강의 : 수강 = 1 : N

잘못된 방법도 기억해 둔다. 강의 테이블에 학생 목록을 콤마로 구분해 저장하는 방식은 정규화되지 않은 방식이라 실무에서 쓰지 않는다.

10. 도서 대여 예시와 ERD에 최소한 보여야 하는 것

한 사람은 여러 권의 책을 빌릴 수 있고, 하나의 책도 (시간을 두고) 여러 사람에게 빌려질 수 있으므로 N:M 구조가 맞다. members, books, loans 세 테이블을 조인해서 다룬다.

ERD에는 최소한 아래 내용이 보여야 한다.

members
books
loans
  - 각 테이블의 PK
  - loans.member_id (FK)
  - loans.book_id (FK)
  - 주요 속성
  - 1:N 관계 표시

11. 실전 설계 포인트

  • 한 행 = 하나의 엔티티 (예: 학생 한 명)
  • PK는 보통 자동 증가하는 id
  • email처럼 값이 중복되면 안 되는 컬럼은 UNIQUE 제약
  • 학번처럼 중복되면 안 되거나 반드시 값이 있어야 하는 컬럼은 UNIQUE 또는 NOT NULL

복습: 헷갈리기 쉬운 포인트

  • WHERE에서 SELECT의 별칭을 쓰면 오류가 난다. (실행 순서: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY)
  • INSERT INTO는 DDL이 아니라 DML이다.
