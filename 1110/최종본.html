Phase 02에서 만든 FastAPI + PostgreSQL(주방) 에 Next.js + React 화면(홀) 을 붙여, 브라우저에서 실제 DB 회원 8명을 조회하는 데까지 완성했다. Phase 03의 1~4강 내용이다.

  • 환경: Windows 11, VS Code, PowerShell, Node v24.19.0, npm 11.17.0, Next.js 16.4.6, React 19.3.0

오늘의 한 줄 정리

  • Props는 받기만, State는 바꾸면 화면이 다시 그려진다.
  • 데이터 가져오기는 fetch + useEffect + Loading/Empty/Error 세 가지 상태 + AbortController 한 세트다.
  • 화면의 입력 검사는 편의일 뿐이고, 최종 검증은 백엔드(Pydantic) 가 한다.

5. 3강: Props, State, Event

의미
Props 부모가 준 택배 (받기만 한다)
State 내가 쓰는 메모장 (바꿀 수 있다)
Controlled Form 입력칸의 value와 State를 onChange로 연결
  • 변수를 그냥 바꾸면 화면이 모른다. 반드시 setXxx()로 바꿔야 다시 그려진다.
  • Server Component(기본) vs Client Component("use client"): useState, onClick은 Client Component에서만 쓸 수 있다. 사용자가 만지는 부분만 "use client"로 떼어낸다.
  • filter() + toLowerCase()로 대소문자를 무시하는 검색을 만들고, event.preventDefault()로 폼 제출 시 새로고침을 막는다.
  • Number.isInteger()로 나이를 검사한다. 화면 검사는 사용자 편의이고, 진짜 문지기는 백엔드(Pydantic) 다.

6. 4강: FastAPI에서 회원 목록 가져오기

용어 비유
fetch 주방에 주문서 보내기
useEffect 화면이 열리면 자동으로 주문
Loading / Empty / Error "조리 중" / "재료 없음" / "주방 문제" 안내판
AbortController 이전 주문 취소 장치
CORS 3000번 문에서 오는 요청을 8000번이 허락하는 설정

API 호출 함수: 응답이 Member[] 모양인지 직접 검사한 뒤 반환한다.

// lib/members-api.ts
export async function getMembers(signal?: AbortSignal): Promise<Member[]> {
  const baseUrl = process.env.NEXT_PUBLIC_API_BASE_URL;
  if (!baseUrl) throw new Error("NEXT_PUBLIC_API_BASE_URL을 설정해 주세요.");

  const response = await fetch(`${baseUrl.replace(/\/$/, "")}/members`, {
    cache: "no-store",
    signal,
  });
  if (!response.ok) throw new Error(`회원 조회 실패: HTTP ${response.status}`);

  const data: unknown = await response.json();
  // Array인지, 각 원소의 필드 타입이 Member와 맞는지 검사 후 return data
  return data as Member[];
}

useEffect로 조회하고, 화면이 닫히면 요청 취소

useEffect(() => {
  const controller = new AbortController();

  getMembers(controller.signal)
    .then((data) => {
      if (controller.signal.aborted) return;
      setMembers(data);
      setError("");
    })
    .catch((caught: unknown) => {
      if (controller.signal.aborted) return;
      setError(caught instanceof Error ? caught.message : "알 수 없는 조회 오류");
    })
    .finally(() => {
      if (!controller.signal.aborted) setLoading(false);
    });

  return () => controller.abort();   // 정리(cleanup)
}, [reloadKey]);                      // reloadKey가 바뀌면 다시 조회
  • "다시 조회" 버튼은 setReloadKey(v => v + 1)로 useEffect를 다시 실행시킨다.
  • 로딩, 오류, 목록 표시는 loading ? ... : error ? ... : <MemberList /> 순서로 분기한다.

7. 설정 파일과 CORS

설정 파일은 누가 읽는지와 비밀값이 들어가는지로 구분한다.

파일 누가 읽나 내용 비밀값
react\.env FastAPI DB 접속 정보, CORS_ORIGINS 있음 (커밋 금지)
member-next-app\.env.local Next.js NEXT_PUBLIC_API_BASE_URL에 FastAPI 주소(로컬 개발 주소) 없음
  • .env / .env.local은 서버가 켜질 때만 읽힌다. 고치면 재시작해야 한다.
  • NEXT_PUBLIC_ 값은 브라우저에 공개되므로 비밀값을 넣지 않는다.
  • CORS에는 Next.js 주소(http://localhost:3000, http://127.0.0.1:3000)를 추가해야 한다. Phase 02는 Live Server(5500)만 허용하고 있었다.

8. Network 탭으로 확인한 것

브라우저 개발자 도구의 Network 탭에서 members 요청 세 줄이 보였다.

줄 Status 의미
members (canceled) Strict Mode 1회차 요청을 AbortController가 취소 (정상)
members 200 실제 조회 성공
members 200 "다시 조회" 버튼으로 재요청

10. 오늘의 핵심 정리와 남은 일

  • Props는 받기만, State는 바꾸면 화면이 다시 그려진다.
  • 데이터 가져오기는 fetch + useEffect + Loading/Empty/Error 세 가지 상태 + AbortController 한 세트다.
  • 화면의 입력 검사는 편의일 뿐이고, 최종 검증은 백엔드(Pydantic) 가 한다.
  • 환경 설정 파일은 누가 읽는지(FastAPI vs Next.js)와 비밀값이 들어가는지로 구분하고, 비밀값 파일은 커밋하지 않는다.

남은 일과 다음 강의는 이렇다.

  • git check-ignore -v .env.local ..\.env로 두 파일이 모두 무시되는지 확인한 뒤 커밋한다. (git add . 대신 파일명을 지정)
  • 5강: 회원 등록 폼에서 POST /members로 실제 DB에 저장하고, 저장 후 목록을 다시 조회한다.
  • 5강에서는 화면 검사(3강)와 백엔드 Pydantic 검사를 함께 사용한다.
