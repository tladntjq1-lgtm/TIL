오전에 이론으로 배운 RAG를 오후에는 직접 코드로 돌려 봤다. AI Agent Engineering 과정의 Lesson 02 미션을 마치고, Lesson 03 코드를 분석한 뒤, Lesson 04에서 RAG 첫 실습을 했다. 오늘 기록의 중심은 두 가지다. 질문과 문서를 단어 집합(set)으로 비교하는 검색, 그리고 max_output_tokens=128에 반복해서 걸린 경험이다.

오늘의 한 줄 정리

  • RAG는 API 기능이 아니라, API를 부르기 전에 내 코드가 하는 "검색 + 근거 붙이기" 과정이다.
  • 공지 파일에서 근거를 찾아 프롬프트에 붙이고 Live로 호출해 답변을 받았다. (input 154 / output 32)
  • 반복해서 만난 한계는 max_output_tokens=128이다. 답이 잘리거나 아예 비어 버렸다.
  • 문자열 비교의 한계도 확인했다. 띄어쓰기 한 칸, 조사 하나로도 검색 점수가 바뀐다.

3. tokenize와 set

1단계: tokenize, 문장을 단어로 자르기

import re

def tokenize(text):
    return [
        word.lower()
        for word in re.findall(r"[가-힣A-Za-z0-9.]+", text)
        if len(word) >= 2
    ]
코드 조각 뜻
[가-힣A-Za-z0-9.] 한글, 영문 대·소문자, 숫자, 마침표 중 하나
+ 그런 글자가 1개 이상 연속된 덩어리
re.findall(...) 문장에서 그런 덩어리를 모두 찾아 목록으로
if len(word) >= 2 한 글자 단어는 버림 (예: 주)
word.lower() 영문을 소문자로 통일
입력 문장 tokenize 결과
과제 제출 기한은 언제인가요? ['과제', '제출', '기한은', '언제인가요'] (?는 빠짐)
이번 주 과제 제출 기한은 금요일 오후 6시입니다. ['이번', '과제', '제출', '기한은', '금요일', '오후', '6시입니다.'] (주는 한 글자라 빠지고, .은 단어에 붙어 남음)
API Key는 로컬 .env 파일에만 저장합니다. ['api', 'key는', '로컬', '.env', '파일에만', '저장합니다.']

한계: 띄어쓰기와 기호로만 자른다. 그래서 문의와 문의는, 입니다와 입니다.를 서로 다른 단어로 본다. "문의 게시판"으로 검색하면 근거를 못 찾는 이유다. 문서에는 문의는, 게시판에처럼 조사가 붙어 있어서 단어가 정확히 일치하지 않을 뿐이다. 이 문제는 Lesson 05 임베딩 검색이 다룬다.

2단계: set, 중복 지우고 종류만 남기기

문서의 과제 제출 섹션을 tokenize하면 단어 15개가 나오고, 그중 과제 3번, 제출 3번이 겹친다. set으로 바꾸면 11종류만 남는다.

section_set = set(section_list)   # 15개 → 11종류

3단계: 두 set을 비교해 score 만들기

question = {'과제', '제출', '기한은', '언제인가요'}
question & section_set            # 교집합 → {'과제', '제출', '기한은'}
len(question & section_set)       # 3  ← score

같은 질문과 섹션이라도 세는 방식에 따라 score가 달라진다.

세는 방식 계산 score 해당 버전
공통 단어 종류 수 질문 set ∩ 섹션 set의 크기 3 내가 쓰는 파일, 강의 설명
나온 횟수 전부 섹션 list를 돌며 질문 set에 있는 단어를 하나씩 셈 (과제 3 + 제출 3 + 기한은 1) 7 다른 버전 docstring

두 방식 모두 질문 쪽은 set이라서 질문에 같은 단어를 여러 번 써도 점수가 오르지 않는다. 차이는 문서 쪽을 set으로 보느냐 list로 보느냐다. tokenize 결과를 바로 보려면(비용 0) 이렇게 실행한다.

python -c "from document_qa import tokenize; print(tokenize('이번 주 과제 제출 기한은 금요일 오후 6시입니다.'))"

4. 실습 결과 기록: 출력 토큰 상한 128

  • Live 호출은 총 8회, 그중 5회가 상한 128에 걸렸다. 문서 근거를 붙인 4강 질문 2회는 모두 여유 있게 끝났다.
  • 같은 입력, 다른 결과: L02 미션은 input 41이 똑같았는데 1차는 빈 응답, 2차는 성공이었다. 한 번 성공했다고 끝내면 안 된다.
  • 구조화 프롬프트의 비용: input이 17 → 160(약 9.4배)으로 늘고 답도 길어져 상한에 더 쉽게 걸린다.
  • RAG의 비용: 근거와 규칙을 붙이면 input이 약 20 → 154로 늘지만, 근거가 짧고 명확하면 답은 짧게 끝난다.
  • 튜터와 결과가 다른 이유: output 32 vs 39는 답 문장 길이 차이이고, score 3 vs 2는 질문 단어가 문서와 정확히 일치한 개수 차이다.
실행 input output 상태 메모
L04 "과제 제출 기한은 언제인가요?" Live 154 32 성공 score=3, 출처 인용 포함
L04 튜터 질문 형태로 재실행 156 37 성공 답 문장이 길어져 output 증가
L03 STEP09 재실행, basic 17 128 PARTIAL 문장 중간에서 잘림
L03 STEP09 재실행, structured 160 128 PARTIAL 형식 검사 T/F/F
L03 "각 소제목 1문장" 요청, structured 179 128 PARTIAL 형식 검사 T/T/F로 개선
L02 미션 1번 Live 2차 41 88 성공 번호 목록 3개, 각 1문장 준수
L02 미션 1번 Live 1차 41 128 PARTIAL 빈 응답. 추론 토큰 소진 추정(미확인)

빈 응답의 원인(추정): 강의 4강 P1도 설명하듯 보이지 않는 추론 토큰이 max_output_tokens 상한에 포함될 수 있다. 상한 128을 추론에 다 쓰면 보이는 답이 남지 않는다. 확정하려면 status, incomplete_details, reasoning_tokens를 확인해야 한다.

튜터와 score가 다름 띄어쓰기 한 칸: 과제 입니다는 과제가 일치, 과제입니다는 불일치 words: 출력으로 질문 단어 set을 확인하고 문서 문장과 비교

6. 셀프 체크 퀴즈

답을 가리고 떠올려 보는 용도다.

  1. "4강 STEP 7 내용 어디 있어?"를 그대로 API에 보내면 RAG일까? → 아니다. 내 코드가 문서를 먼저 검색해 근거를 붙여야 RAG다.
  2. 채팅에서 "아까 내가 뭐 물었지?"에 답할 수 있는 건 RAG 덕분일까? → 아니다. 이전 대화가 매번 다시 전달되는 Memory 방식이다.
  3. 같은 질문(input 41)인데 한 번은 빈 응답, 한 번은 정상이었다. 왜? → 모델은 매번 다르게 동작하고, 보이지 않는 추론 토큰이 상한 128을 다 쓰면 보이는 답이 남지 않는다(추정).
  4. 빈 응답이 나왔을 때 --fallback gemini가 켜져 있었다면 Gemini로 넘어갔을까? → 아니다. 빈 응답은 오류(Exception)가 아니라서 폴백 조건에 걸리지 않는다.
  5. 문서에 과제가 다섯 번 있는데 질문 "과제"의 score가 1인 이유는? → 공통인 단어 종류 수를 세기 때문이다. 최댓값은 질문 단어 종류 수다.
  6. score가 높으면 그 문단으로 답을 확정해도 될까? → 아니다. score는 일치한 단어 수일 뿐이다. "과제 제출 후 환불이 가능한가요?"처럼 문단이 검색돼도 답이 없을 수 있다. 검색 성공과 근거 충분은 다르다.
  7. here-string을 | python으로 넘겼더니 한글이 ??가 됐다. 원인과 해결책은? → PowerShell 5.1 파이프 기본 인코딩이 ASCII다. $OutputEncoding을 UTF-8로 바꾸거나 파일로 저장해 실행한다.
  8. "문의 게시판"으로 검색하면 근거를 못 찾는다. 문서에 문의 방법이 없다는 뜻일까? → 아니다. 문의는, 게시판에처럼 조사가 붙어 있어 단어가 정확히 일치하지 않을 뿐이다. Lesson 05 임베딩 검색이 이 문제를 다룬다.
